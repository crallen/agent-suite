# agent-suite

A custom suite of software engineering agents, skills, and commands, shared across
Claude Code, OpenCode, and Codex.

Extracted from the `dotfiles` repo — it was `claude/.claude/` and the agent-suite
half of `opencode/.config/opencode/`, with its history intact.

## Repo Layout

```text
agent-suite/
├── AGENTS.md               # The suite's global operating instructions and index
├── agents/                 # Specialist subagent definitions
├── skills/                 # Skills — methodology skills plus the /-command workflows
├── platforms/
│   └── opencode/           # OpenCode's copies: agent/, commands/, skills/, AGENTS.md
└── scripts/
    ├── sync-skills.sh      # Regenerate the OpenCode skill copies
    └── validate-config.py  # Reference integrity, index accuracy, shared-skill parity
```

The top level is the canonical suite. `platforms/` holds per-platform copies, which
exist because the harnesses differ in what they need — OpenCode's skill loader
requires a `name:` frontmatter key, and it keeps commands in their own tree rather
than as skills.

## Working here

`skills/<name>/` is the single source of truth for every shared skill. The
`platforms/opencode/` copies are generated by `scripts/sync-skills.sh`, which adds the
`name:` key and applies a small platform-vocabulary substitution table. Editing a
copy directly is silently overwritten on the next sync.

```sh
scripts/sync-skills.sh           # regenerate the opencode copies
scripts/sync-skills.sh --check   # report drift, exit 1 (CI / pre-commit)
```

`scripts/validate-config.py` is the broader check — reference integrity (agent → skill,
command → agent, skill → reference file), index accuracy in `AGENTS.md` and
`platforms/opencode/AGENTS.md`, frontmatter validity, and shared-skill parity. It runs
in CI via `.github/workflows/validate.yml`. Run it after any change to an agent, skill,
command, or either index document:

```sh
scripts/validate-config.py        # list every check and what it covered; exit 1 on any problem
scripts/validate-config.py -q     # only failures and the summary, for a git hook
```

One skill is deliberately not synced and stays hand-maintained on both sides:
`agent-authoring` (it documents each platform's own schemas) — the only entry in the
script's `SKIP`. Sharing is otherwise opt-in by existence: a skill syncs only if
`platforms/opencode/skills/<name>/` already exists, which is why the `/`-command
workflow skills need no SKIP entry.

## Installation

Nothing here is wired into a live config yet. `dotfiles` still carries its own copy
under `claude/` and `opencode/`, and remains the thing that gets stowed.

## Conventions

- Commits use Conventional Commits, scoped by area (`feat(skills):`, `chore(scripts):`).
- Changes to a shared skill touch both the canonical and platform copies, and must be
  committed together under the `skills` scope.
- Never read or commit secret-bearing files (`.env`, keys, credentials).
